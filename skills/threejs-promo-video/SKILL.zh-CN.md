# three.js 宣传片

[English](SKILL.md) | 简体中文

目标是做出清楚、可信的短片：一句话痛点 → 产品分三步完成一件真实的事 → 品牌落版。全部画面由代码生成（three.js 场景 + 2D 叠加层），每一帧只取决于时间 t，用无头浏览器逐帧渲染后直接送进 FFmpeg。重渲结果完全一致，一般一分钟左右出片。

## 何时阅读参考资料

- 规划叙事、字幕、数据口径，或匹配公司已有宣传片风格：读 [叙事与风格](references/story-and-style.zh-CN.md)。
- 搭建、渲染、调试场景，以及交付前检查：读 [渲染与质检](references/rendering-and-qa.zh-CN.md)。

## 流程

1. **收集素材**：产品录屏或截图（越真实越好）、受众（用户 / 投资人 / 大会）、时长、语言版本、公司参考片。只问自己查不到的。
2. **研究参考风格**（如有参考片）：运行 `scripts/contact_sheet.sh <参考片.mp4>`，再看左上角标识、字幕、面板、结尾的全分辨率帧。记下配色、顶栏布局、字幕体系、面板处理和落版，照这套规范做，不另起炉灶。
3. **先写叙事**（见参考资料）：痛点 → ① 输入 → ② 执行与把控 → ③ 结果 → 落版。一个镜头只讲一件事。画面上的每个数字都要有出处，并标注口径（如「实测」「试运行参考」）。
4. **挑真实画面**：优先用不带字幕的原始录屏。用 FFmpeg 抽帧，逐张看全分辨率图，记下相机取景 `frame` 和高亮 `spot` 的像素矩形。内部域名、IP、密钥、客户数据要先打码再用。
5. **搭工程**：把 `assets/template/` 复制到用户仓库以外的工作目录，`npm install`，再把 `storyboard.example.json` 复制为 `storyboard.json`。模板自带虚构示例截图（`npm run sample-shots`），可以直接渲染。
6. **编辑 `storyboard.json`**：品牌、主题色、logo、开场钩子、步骤、各语言字幕、镜头（`img` 或图片序列、`frame`、可选的 `frame2` 和 `pan`、`spot`、`call`、可选 `checks`）、落版。只有需要新的视觉手法时才改 `public/main.js`。
7. **出静帧检查**：`node render.mjs --stills 2,5,8,... --lang <语言>`，拼成联系表查看。修掉遮挡、看不清的字和元素冲突，直到干净。
8. **生成配乐**：`node gen-audio.mjs`。音效时间点从 storyboard 推导，改了时间就要重跑。
9. **逐语言出片**：`node render.mjs --video out-<语言>.mp4 --audio music.wav --lang <语言>`。再对成片运行 `scripts/contact_sheet.sh`，检查时长、响度（约 −14 到 −13 LUFS）和画面。
10. **如实汇报**：哪些检查过（静帧 / 联系表），哪些没做（完整播放 / 试听）；哪些镜头来自与叙事不同的运行；哪些地方打了码；哪些数字标了参考口径。

## 关键原则

- 清楚优先于炫技：一个镜头如果需要一句话解释，就配字幕或标注；不承载信息的特效删掉。
- 展示真实产品，并在画面上标明（如「画面为真实运行录屏」）。不要伪造看起来像真的界面；必要的重演（如逐字输入）必须用产品里的真实文本。
- 1080p 下屏幕上的字至少约 28 px。真实界面要放大 2–3 倍，整屏截图直接放是看不清的。
- 底部字幕区（约 200 px）和顶部标识区（约 160 px）不放内容；标注气泡会自动翻到高亮区域的上方或下方。
- 品牌：有官方 logo 文件就用官方文件；如果是重画的标识，要明确告知。
- 双语版本指每种语言有各自的字幕和标注；截图里的产品界面语言不会跟着变，需要时要说明。
