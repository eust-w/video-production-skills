# 叙事与风格

[English](story-and-style.md) | 简体中文

## 两种验证过的结构（30 秒）

**A. 真实路径（默认推荐）**：可信度来自真实产品。

| 时间 | 段落 | 画面 |
| --- | --- | --- |
| 0–3 秒 | 痛点钩子 | 一个画面讲清痛点，例如 AI Agent 自称「已完成，测试全部通过」，被盖上「未经验证」 |
| 3–10 秒 | ① 输入 | 放大真实输入界面：一句话想法，再到 AI 补全的验收标准逐条勾选 |
| 10–19 秒 | ② 执行与把控 | 阶段推进（图片序列）、测试证据（退出码）、人工审核关口 |
| 19–25 秒 | ③ 结果 | 部署健康、可回滚、可追溯的发布记录 |
| 25–30 秒 | 落版 | logo、产品名、标语、「××出品」 |

右上角常驻三步进度条，让观众知道现在在哪一步。每个产品镜头只有一个高亮区和一个标注气泡。

**B. 概念讲解**：还没有能展示的界面时使用。结构是痛点 → 一句话产品 → 两个技术支柱的可视化（例如执行与验证分离、跨防火墙的签名拉取式交付）→ 数据卡 → 落版。用 three.js 的卡片和示意图场景实现。讲架构更清楚，但说服力不如 A；一旦有真实录屏，就建议改成 A。

## 写给用户和投资人

- 先用大白话讲痛点（「AI 写代码越来越快，但没人敢直接上线」），再给一句话产品承诺。
- 技术深度 = **点名的机制 + 证据**，不是形容词。例如「隔离 Pod、退出码 0」「签名发布、零入站端口」「健康探针失败自动回滚」。
- 一个镜头一个点，一个段落一句字幕。中文主字幕超过约 20 字、英文超过约 55 个字符就删词；模板会自动缩小字号，但那是最后手段。
- 标注写高亮区域「证明了什么」，而不是「它是什么」（写「6 项通过，退出码 0」，不写「测试日志」）。

## 数字与口径

- 每个数字都要有出处（文档 / 看板 / 实测），并在画面上标注性质：「实测」「试运行参考」「设计上限」。初步数据要加画面注脚；投资人材料里用软数据前，先问负责人能不能对外说。
- 不要在不告知需求方的情况下，把不同运行的画面拼成「同一次运行」的故事。优先用同一次运行的画面，或裁切到不会造成误导，并在交付说明里写明。
- 内部域名、IP、镜像仓库路径、密钥、邮箱、客户名要打码或裁掉。FFmpeg 做法：对静帧 `split → crop → boxblur → overlay`。

## 从参考片提炼公司风格

1. `scripts/contact_sheet.sh ref.mp4 sheet.jpg 1 6` 看整体节奏；再抽 3–5 张代表性时刻的全分辨率帧（顶栏、字幕、面板、数据卡、结尾）。
2. 把风格记成具体参数：底色（如暖黑 + 红棕径向光）、强调色、纹理（如边缘更亮的点阵）、顶栏布局（logo · 产品名 / 章节编号）、字幕体系（粗体主字幕 + 小号宽字距英文大写副字幕）、面板处理（深色玻璃 + 强调色辉光描边 + 底部光带）、数据卡样式、落版（标识 + 产品名 + 标语 + 英文副标）。
3. 映射到模板：`theme.accent/accent2/background/haze/dots`、`brand.logo` 或 `monogram`、字幕的 `sub`、落版字段；尽量沿用对方的字体。
4. 用公司官方 logo 文件。重画的标识只是占位，必须告知。

## 双语版本

- 每种语言单独写字幕，不要逐字翻译。中日韩语言版本里，模板会在主字幕下自动显示英文大写小字（常见的双语宣传片规范）；英文版则在 `sub.en` 里写一句短标语。
- 卡片文字、阶段名、标注都随 `--lang` 切换。产品截图保留原界面语言，需要时说明，或用目标语言界面重新录制。
