# 产品演示视频

[English](SKILL.md) | 简体中文

把可运行产品变成面向用户的演示：可识别的问题、清晰操作、可见结果，以及下一步。交付可播放视频、同步 SRT 和干净的旁白稿。

## 默认值与范围

- 使用 [assets/voice-profile.json](assets/voice-profile.json) 中可配置的默认自然女声 `zh-CN-XiaoxiaoNeural`，正常语速、音调和音量。尊重用户选择的语言与声音；明确要求优先于默认值。所选声音不可用时说明具体失败，不静默切换到 macOS `say` 或其他声音。
- 默认中文产品旁白，介绍用户问题、收益与操作流程。除非用户要求，将开发状态、分支、测试数量和实现报告放在独立证据中。代码编辑产品仍应展示其代码相关功能。
- 按本次范围确定时长和章节数，不继承上次项目的长度或章节要求。复用方法和声音，不照搬产品名、品牌、选择器、资源标识或结论。
- 除非用户要求提交媒体，把录屏、音频、临时脚本与导出放在源码仓库外的任务专属目录。保留已交付版本。

## 工作流程

### 1. 确定可展示内容

阅读相关产品文档、当前界面与已有产物。用户要求测试或本地启动时，完成相应检查，但将这些证据与影片叙事分开。使用已有授权服务，保留无关进程与数据。

将演示分为真实操作、明确模拟的数据、不可用功能。每个镜头对应可观察结果。模拟适配器或准备的数据集应持续显示“演示数据”等符合视频语言的标签；缺失集成应表述为产品配置前提，不暗示成功。录屏不构成生产变更、付费订阅、对外发布或向他人发送真实通知的授权。

**完成条件：** 每项拟展示能力都有录屏来源或明确边界，大纲中没有无依据承诺。

### 2. 编写产品故事

围绕用户任务组织演示，不按内部模块逐项巡览。使用用户会输入的自然问题、简洁口语与合理转场。旁白解释可见操作为何有价值，明确区分证据、假设和下一步。

片头、可选转场与结尾使用当前产品品牌。需要轻量标题卡时，修改 [assets/title-card.html](assets/title-card.html) 中产品名、文案和强调色，主体优先展示真实界面。规划或修改脚本、取舍镜头时阅读 [故事与审阅](references/story-and-review.zh-CN.md)。

合成前确定每章 `narration`。显示字幕为准；可用显式发音映射将缩写拼读，但不能改变含义。参考 [计划模板](assets/plan.example.json) 与 [媒体契约](references/media-contracts.zh-CN.md)。

**完成条件：** 脚本符合产品介绍口吻，准确匹配拟展示画面，无待定文案，可直接合成。

### 3. 录制真实操作

优先使用支持所需录制的现有浏览器／录屏集成，遵守其工具规则。不可用或不能录制时使用普通 Playwright 并记录原因。发现实际运行时和浏览器路径，不复制旧电脑路径。

使用 Playwright 时，观察真实界面后改写 [assets/scenario.example.cjs](assets/scenario.example.cjs)，通过 `scripts/record.cjs` 录制。保持 viewport 和 screen 尺寸一致，检查实际全屏录像，不把点击成功当成画面可用。

准备干净且获授权的演示上下文。自然产品问题、具名示例会话通常比冗长测试指令更适合视频。破坏性界面功能只在本次演示创建的可丢弃记录上操作。真实对外发送需要用户授权，否则使用明确标注的模拟投递。

记录操作和结果标记、相关页面错误与截图。关闭页面／上下文使录像落盘后才能视为完整。保留失败片段，明确选择最终 take。刻意展示的错误必须标为错误结果，不能说成能力成功。状态、流式响应、打印导出与时间问题见 [录制实践](references/recording.zh-CN.md)。

**完成条件：** 选定片段展示真实操作与结果，源视频已完成写入并可检查。

### 4. 合成所选声音与字幕

通过显式计划和输出目录调用 `scripts/narrate.py`。默认离线验证；`--generate` 才执行在线合成。安装与数据结构见 CLI 帮助和 [媒体契约](references/media-contracts.zh-CN.md)。

只发送已审阅旁白，不发送令牌、私人配置、客户记录或原始调查数据。保留服务的句／词边界，不能平均切分音频时长编造字幕时间。修正轻微边界重叠或引号缺失时，保留原始元数据和完整文本覆盖。

脚本变化后重新生成相关音频与字幕，检查实际解码与内容覆盖。修改声音参数、语言或用户要求试听时先试听短段；默认声音本身无需重复确认。

**完成条件：** 每章声音正确、旁白完整，有真实时间元数据，文本和音频哈希匹配。

### 5. 剪辑与合成

从源录屏建立明确的剪辑决策表。去掉无效等待，让结果保留足够阅读时间，并与相应讲解对齐。使用实际媒体时长和已检查裁切点，不使用估算或页面创建时间。

用 `scripts/compose.py` 输出 MP4、SRT、章节和来源信息。字幕放在独立字幕带，避免挡住操作；字号和品牌色适合产品。为对话和图表留出阅读时间，说明显著变速。可短暂保持结果帧，长时间冻结通常需要收紧脚本或重录。

裁切可突出结果或排除无关内容，但要保留证据与不确定性。检查报告正文、导出文档与删除后的回退界面：旁白改过后，这些位置仍可能残留开发文案。不能伪造界面响应或成功画面填补缺失录屏。

**完成条件：** 选定版本包含正确片段、最新声音与字幕、适当数据标签，以及围绕产品的开头和结尾。

### 6. 验证与交付

运行 `scripts/verify.py` 检查解码、流／章节／SRT 一致性、哈希和代表帧，再查看文字图表、全屏、导出、确认弹窗、转场、结果帧及修改过的镜头。技术解码通过不能证明视觉或声音质量合格。

镜头变化后更新相关剪辑／音频，重新构建，并将检查绑定到新文件及哈希。检查受影响画面与成片，不反复运行无关应用测试。

突出交付最终 MP4，同时提供 SRT 和带真实章节时间的旁白稿。详细测试与来源证据单独保存。简要说明重要剩余限制。在 Codex 中使用绝对本地 Markdown 媒体路径展示视频。

**完成条件：** 交付的是已检查的最终文件，可正常打开，无未说明的缺失镜头、音画不一致或无依据成功声明。

## 可复用工具

- `scripts/narrate.py`：所选神经声音、服务时间字幕、文本一致性和合成清单。
- `scripts/record.cjs`：浏览器录制封装，实际产品操作由 scenario 提供。
- `scripts/compose.py`：剪辑合成、字幕带、响度归一化、章节与来源信息。
- `scripts/verify.py`：媒体完整性和时间检查，之后仍需画面审阅。
- [媒体契约](references/media-contracts.zh-CN.md)：依赖、命令、数据结构与端到端示例。
