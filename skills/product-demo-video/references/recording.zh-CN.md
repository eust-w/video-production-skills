# 录制实践

[English](recording.md) | 简体中文

## 录制路径

存在支持任务的浏览器／录屏集成时优先使用并遵守其说明，否则使用可移植 Playwright 封装。启动服务前检查已有应用脚本与端口，保留用户当前浏览器和无关服务。

封装创建独立浏览器上下文，只记录 scenario 的实际页面。可使用明确获授权的已保存认证上下文，但应放在 Skill 外且不输出。工具不提供应用访问授权、不种数据、不发消息，也不实现产品功能。

## 状态与关联

- `viewport` 和 `screen` 保持一致。无头模式点击全屏可能进入更小显示区域，检查 `innerWidth/innerHeight` 并抓帧比较。可以合理裁切真实全屏画布，但不能把丢弃的灰区说成可用录像。
- 一次性初始会话选择不能由 init script 每次重载都强制写入，否则刷新看起来可能恢复错误会话。
- 流式产品应等待**新一轮运行**的文本或流式标记，不是页面已有答案。尽可能关联当前 run／消息；旧答案可见不代表新响应已开始。
- 选择器限定在活动面板，主聊天与管理面板可能共用输入标签。
- 零高度空消息容器可能已挂载但不可见，应等待有实际意义的就绪条件，不只断言可见。
- 避免通过 PTY 传输长 JSON／程序字符串，终端输入限制可能截断内容。将 scenario 存成文件后传路径。

## 时间与保留

保留原始 take 和明确剪辑选择。相对页面创建的 marker 时间只是近似值，设置裁切点前查看首帧及实际文件时长。关闭页面／上下文使视频完成写入。失败时保存 take 和诊断，返回失败，再局部恢复或重录。

多个原始 take 合成时保留各自路径与裁切决策，不把单段的墙钟时间范围当成合成片时间。不能静默操纵状态制造目标画面。

## 打印与下载

操作应用真实导出控件，检查实际下载产物。无头 PDF 捕获保留产品打印组件与浏览器打印引擎。若拦截 `window.print()` 通过浏览器 API 保存，应描述为自动浏览器打印，而不是系统打印对话框录屏。

过早强制 print media 可能让响应式图表以错误宽度重测并裁切。渲染已保存 PDF 各页，检查全部节点与文字。可用以用户用途命名的干净预览展示导出文档，不加入运行时实现标签。
